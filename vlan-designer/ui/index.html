Every VLAN present on an access port also needs to reach the router — so one port is automatically a trunk port, carrying all of them at once.

How a Trunk Actually Carries Multiple VLANs ?

A trunk port inserts a 4-byte 802.1Q tag into each Ethernet frame, recording which VLAN it belongs to — that's the entire mechanism:

  • Access ports never see this tag — the switch adds it the instant a frame enters a trunk, and strips it the instant a frame leaves onto an access port. Only trunk links ever carry tagged frames.
  • This is exactly why a trunk can carry many VLANs on ONE physical cable: the tag is the only thing separating them.

The Alternative: an L3 Switch ?

Instead of a separate router, a Layer 3 switch can do this routing internally using SVIs (Switched Virtual Interfaces) — one virtual interface per VLAN, living inside the switch itself. No external router, no physical trunk link needed just for routing. Faster (routing happens in hardware) and simpler to cable, but requires L3-capable switch hardware, which costs more than a plain Layer 2 switch.

    Why Redundant Links Need Something Like STP ?

    A fixed illustrative scenario: two switches connected by TWO links for redundancy — if either cable fails, the other keeps things connected. But plugged in as-is, this creates a loop, and unlike IP packets, Ethernet frames have no TTL to stop them circulating forever.

    Bridge Priority — Electing the Root Bridge ?

    Lower priority wins. Real switches use increments of 4096 (0–61440); ties are broken by the lowest MAC address — Switch A is fixed as the tiebreak-winner here for a predictable example.
